# SchemaForge

Build **SchemaForge**, a personal AI-powered database engineering workspace.

Do not assume a specific programming language, framework, database, AI provider, hosting platform, or architecture unless required by an implementation decision. Choose modern, flexible, lightweight technologies that support the product requirements below.

This is primarily a **personal development tool**, not a SaaS product. Optimize for developer experience, flexibility, speed, low operating cost, local development, and the ability to evolve the system over time.

The application should combine:

* Database IDE
* Database schema explorer
* Schema visualization
* SQL workspace
* Query analysis
* Database documentation
* AI database assistant
* AI coding workspace
* Multi-agent orchestration
* Agent monitoring and control
* Project/workspace management

The core goal is:

> **Give me one visual workspace where I can understand databases, work with SQL, and delegate database/software-engineering tasks to multiple AI agents while seeing exactly what those agents are doing.**

---

# 1. CORE PRODUCT CONCEPT

SchemaForge is not simply a database administration tool with an AI chatbot attached.

AI agents are a first-class part of the application.

The application should allow me to:

* connect to databases
* inspect database structures
* understand relationships
* visualize schemas
* write SQL
* generate SQL using natural language
* execute SQL
* analyze SQL
* analyze query performance
* create schema changes
* generate migrations
* review database designs
* document database structures
* ask AI questions about the database
* create development tasks
* assign tasks to AI agents
* run multiple agents simultaneously
* monitor agents
* control agent execution
* review agent outputs
* approve sensitive actions
* maintain persistent project context
* reuse previous work

The application should feel like a combination of:

**Database IDE + AI coding environment + multi-agent control center.**

# 18. DANGEROUS DATABASE OPERATIONS

SchemaForge must protect against accidental destructive operations.

Classify operations.

Safe:

```text
SELECT
EXPLAIN
Schema metadata
Read-only inspection
```

Potentially destructive:

```text
INSERT
UPDATE
DELETE
CREATE
ALTER
DROP
TRUNCATE
Migration execution
```

Destructive or high-impact operations should require explicit approval unless the user has deliberately configured an appropriate trusted policy.

AI should never silently execute destructive database changes.

# 53. ENGINEERING PRINCIPLES

Follow these principles:

* Keep modules loosely coupled.
* Prefer simple architecture.
* Avoid unnecessary dependencies.
* Avoid premature abstractions.
* Keep provider-specific code isolated.
* Keep agent execution isolated from UI.
* Keep tools independent from agents.
* Treat events as first-class data.
* Treat artifacts as first-class data.
* Preserve execution history.
* Make destructive operations explicit.
* Keep secrets secure.
* Optimize AI context.
* Avoid unnecessary AI calls.
* Design for local-first development.
* Keep deployment flexibility.
* Make future integrations possible without making the initial system complex.
